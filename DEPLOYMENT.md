# Deployment Guide (Render Free Tier & Docker)

This repository includes deployment templates for **Render Free Tier** (`render.yaml`), standalone **Prisma** migrations (`prisma/`), and **Docker** (`Dockerfile`, `docker-compose.yml`).

## 1. Render Blueprint Deployment (`render.yaml`)

1. Push this repository to GitHub.
2. In the Render Dashboard, choose **New -> Blueprint** and select your repository.
3. Render automatically reads `render.yaml` and provisions:
   - **Managed PostgreSQL** (`amharic-lyrics-db`, Free plan)
   - **Web Service** (`amharic-lyrics-api-platform`, Node runtime, Free plan, health check `/health/ready`)
4. Configure the remaining prompt/secret environment variables in Render:
   - `CORS_ORIGIN`: Your production frontend/portal origin (e.g. `https://amharic-lyrics-api-platform.onrender.com`)
   - `GOOGLE_CLIENT_ID`: OAuth 2.0 Web application client ID from Google Cloud Console.
   - `ADMIN_EMAIL`: Optional allowlisted, verified Google administrator email; there is no default admin email.
   - `ADMIN_PASSCODE`: Unique random secret of at least 32 characters to enable password-based first-run admin bootstrap. Without it, that bootstrap flow stays disabled.
   - `JWT_ACCESS_SECRET` & `JWT_REFRESH_SECRET` are auto-generated by `render.yaml`.
5. Render runs the build command:
   ```bash
   npm install
   npx prisma generate
   npx prisma migrate deploy
   npm run build
   ```
   and starts the server with `npm start` (`node server.ts`), binding to `0.0.0.0` on `process.env.PORT`.

For Google sign-in, create an OAuth 2.0 **Web application** client in Google Cloud Console, add the deployed site origin under **Authorized JavaScript origins**, and set its client ID as `GOOGLE_CLIENT_ID` in the server environment. Add `http://localhost:3000` as an authorized origin for local development. The client ID is public; do not put a client secret in the app.

## 2. Seeding Production Lyrics (Optional)

To populate the curated Amharic lyrics catalog (demo tracks + the 28 extracted songs) on a fresh deployment database:

```bash
npx prisma db seed
```

The seed is idempotent: songs already present (matched by title + artist) are skipped, so it can be
re-run safely against an existing database.

For the local Drizzle runtime database, use:

```bash
npm run db:seed
```

## 3. Standalone Docker Production Build

Build and run the multi-stage container image. Put `SQL_PASSWORD`, `JWT_ACCESS_SECRET`,
`JWT_REFRESH_SECRET`, and (if using password-based admin setup) `ADMIN_PASSCODE` in a protected
`.env.production` file before running:

```bash
docker build -t amharic-lyrics-platform .
docker run --env-file .env.production -p 3000:3000 \
  -e NODE_ENV=production \
  -e PORT=3000 \
  -e SQL_HOST=host.docker.internal \
  -e SQL_USER=postgres \
  -e SQL_DB_NAME=amharic_lyrics \
  amharic-lyrics-platform
```

## 4. CI/CD Workflows

GitHub Actions workflows are included under `.github/workflows/`:
- `lint.yml`: TypeScript checks (`npm run lint`)
- `test.yml`: Vitest + Supertest suite (`npm test`)
- `build.yml`: Production Vite bundle verification (`npm run build`)
- `security.yml`: Dependency audit checks
